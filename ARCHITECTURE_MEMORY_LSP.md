# Architecture: Memory and LSP Implementation

This document outlines the implementation of persistent memory, consistent memory, and Language Server Protocol (LSP) integration within the Sapphire CLI.

## 1. Persistent Memory (Long-Term Task Context)

Sapphire handles long-horizon tasks by persisting session state, task breakdowns, and history to a local SQLite database.

### Core Components

- **Session Storage**: All conversation metadata and token usage are stored in SQLite.
- **Task Management (Todos)**: The explicit `todos` tool forces the agent to externalize its plan into the database.
- **File Tracking**: Every file read is recorded to provide context for future operations within the session.

### Key Files

- `internal/db/sql/sessions.sql`: Database schema for persistent sessions and todos.
- `internal/session/session.go`: Service for managing session lifecycle and persistence.
- `internal/agent/tools/todos.go`: Tool for structured task tracking.
- `internal/filetracker/service.go`: Persistent tracking of file access history.
- `internal/agent/coordinator.go`: Management of hierarchical and delegated sessions.

## 2. Consistent Memory (In-Session Context)

Consistent memory ensures the agent maintains persona, instructions, and context throughout a session.

### Mechanism: Long-Horizon Context Management

The CLI maintains long-horizon consistency by transforming raw conversational history into compressed, structured summaries.

- **Trigger**: Automatic summarization occurs when session token counts exceed model limits.
- **Process**: `internal/agent/agent.go:Summarize` is invoked, which:
  1. Fetches current session messages.
  2. Uses a specialized system prompt (`summary.md`) to extract core insights and the current `todos` state.
  3. Streams the summary to a new `IsSummaryMessage` in the session history.
  4. Truncates the raw message chain to maintain a compact context window for subsequent turns.
- **Result**: The agent receives a condensed yet representative history, preventing context overflow while preserving intent over hours of operation.

### Core Components

- **System Prompting**: Tailored templates define the agent's behavior and tool usage protocols.
- **Automatic Summarization**: Large contexts are compressed into summaries when token limits are approached via `internal/agent/agent.go:Summarize`.
- **History Management**: Dynamic construction of the message chain from stored history.

### Key Files

- `internal/agent/agent.go`: Orchestrates prompt construction and summarization logic (contains `Summarize` and `buildSummaryPrompt` methods).
- `internal/agent/templates/coder.md.tpl`: Primary system instructions for the coding agent.
- `internal/agent/prompts.go`: Template loading and initialization logic.
- `internal/agent/templates/summary.md`: Specialized prompt for context compression.
- `internal/config/config.go`: Contains `DisableAutoSummarize` configuration flag.
- `internal/ui/dialog/commands.go`: Defines the `summarize` command for manual session summarization.

## 3. LSP Integration (Semantic Intelligence)

LSP provides semantic understanding of the codebase, enabling real-time diagnostics and symbol navigation.

### Core Components

- **Lifecycle Management**: Lazy-loading of language servers based on file types and root markers.
- **Semantic Tools**: Direct agent access to compiler diagnostics and symbol references.
- **Reactive Updates**: Decoupled event system for broadcasting diagnostic changes to the UI and agent.

### Key Files

- `internal/lsp/manager.go`: Handles starting, stopping, and managing multiple LSP clients.
- `internal/lsp/client.go`: High-level wrapper for LSP communication (using `powernap`).
- `internal/agent/tools/diagnostics.go`: Tool for retrieving compiler errors/warnings.
- `internal/agent/tools/references.go`: Tool for semantic "find usages" navigation.
- `internal/app/lsp_events.go`: Event broker for asynchronous LSP notifications.
