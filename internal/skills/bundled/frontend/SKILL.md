This is a compatibility entrypoint, not a separate frontend methodology.

For real frontend work, use the full bundled frontend skill pack:

1. If design context is missing, load `learn-frontend-context` first.
2. Load `frontend-design` for the main frontend implementation rules.
3. Use `search_skills` to discover follow-up frontend skills such as `audit`, `normalize`, `polish`, `critique`, `harden`, `bolder`, `distill`, `animate`, `colorize`, `typeset`, `optimize`, `adapt`, `arrange`, `clarify`, `delight`, `extract`, `onboard`, `overdrive`, and `quieter`.
4. Load only the specific follow-up skills needed for the task.

Do not treat this `frontend` skill as an alternative to `frontend-design`.
It exists only so older flows that ask for `frontend` still resolve into the full frontend pack without ambiguity.
